The multi-week job ledger, client-scoped variation authority, cumulative progress-claim reconciliation and native SQL concurrency integration are Plinth work. All money enters as bounded integer AUD cents; whole-number quantities extend into checked cent totals. Issued commitments and accepted receipts are shown separately from the contract and claim amounts. The report prepares external bookkeeping and is neither an invoice nor a statutory payment claim.

Each direct `/api/plinth/**` request authenticates using Base's native session or native fenced credential. Native member accounts are clients only for jobs whose client email matches. Owner/admin sessions manage jobs. A bearer credential, even when minted by an owner, has draft preparation authority and cannot approve, accept, issue, receive, export or erase. Mutation batches repeat authority and record-version checks inside the real D1 transaction. Owner erasure uses the shared portability erasure checkpoint through `src/plinth/import-erasure.ts` as well as native tombstones, so restoring an old journal cannot revive erased custody.

`tests/plinth/domain.test.mjs` exercises the end-to-end lifecycle through actual Worker HTTP handlers and migrated Miniflare D1, with native invitations, local outbox confirmation and native credential step-up. Import lifecycle tests share the same fixture. No application mock or fallback service is used.

## Plinth visual assets

The mark is original Plinth artwork. The terrazzo source crop comes from 12ui’s conversion of Plinth’s selected hero slab. `scripts/brand/terrazzo.py` recreates both the seamless texture and empty Lobby slab; diary examples use neutral empty photo tiles. Albert Sans is self-hosted under its OFL licence, with provenance in `public/fonts/README.md`. The run-site section components and app styling implement the selected Plinth design. The native operator-auth source remains byte-exact to the recorded Base revision; Plinth styles it through its declared theme.
