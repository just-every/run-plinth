# Private manual agent runs

A run holds one owner's explicit source selection and fixed native action plan for one job. It does not call a model. It grants no new agent, provider or recipient permission. Source notes remain untrusted facts, including instructions to send money or bypass a rule.

Use a signed-in owner session to submit `POST /api/plinth/agent-runs/preview`. Supply the current `job_id` and `expected_job_version`, an explicit `diary_ids` array, `steps`, and `limits`. An empty source array selects only the job identity, name, status and currency. Daily log sources include only the selected identity, date, note and state; client contact details, private costs and other job records are omitted.

The only steps are `{"tool":"plinth.jobs.get"}` and `{"tool":"plinth.diary.prepare","input":{"date":"2026-10-29","note":"Private reviewed draft"}}`. The read returns the captured packet, rather than broadening to the current job. There may be at most eight steps and one daily log draft. A draft date must be explicit. There is no attachment, publication, approval, sending, financial, import, export or erasure step.

Inspect the returned packet and plan. Submit the same values to `POST /api/plinth/agent-runs`, adding the preview's `digest`, `confirm: true` and an approval `reason`. A source or plan change invalidates the digest. Existing credentials and company agent policy must also permit the call; this approval cannot override either.

Over MCP, use `plinth.runs.list` and `plinth.runs.read` to inspect approved run identities and their packets. `plinth.runs.continue` accepts `run_id`, the exact zero-based `sequence`, and the shared door's `idempotency_key`. Each continuation executes one approved native step. Different transport keys for an already completed sequence return the same checkpoint and actual draft identity. A concurrent conflict is safe to retry at that same sequence. Draft and checkpoint commit together, so a restart cannot leave an uncheckpointed duplicate.

`limits.max_tool_calls` bounds successful native steps from one to eight. `limits.max_payload_bytes` bounds cumulative serialized native step inputs and outputs, up to 65,536 bytes; the envelope has a separate hard size limit of 65,536 bytes. Reading the control envelope does not consume a native step. A reached limit records a failed state before any further draft is saved. The owner can inspect state, failure code, progress, source references and each draft identity through `GET /api/plinth/agent-runs/{id}`. Measurements report native steps, payload bytes and native elapsed milliseconds. Model usage and provider cost remain unknown; these counters do not enforce a provider token or spending budget.

An owner may submit `pause`, `revoke` or `cancel` to `POST /api/plinth/agent-runs/{id}/{action}` with `expected_version`. Pause prevents later work and cached checkpoint disclosure to an agent until fresh owner review. Revocation and cancellation are terminal. Current source revisions, active sponsor, credential, company pause and exact run consent are checked before continuation and before any committed write. A source edit needs a new manual run.

Private archives retain packets, source references, checkpoints and draft identities. Execution consent and schedule consent are excluded. In the receiving installation, an owner previews `GET /api/plinth/agent-runs/{id}/preview`, then submits its new digest, `confirm: true` and `expected_version` to `POST /api/plinth/agent-runs/{id}/review`. An archived digest alone cannot restore authority. A paused run uses the same review door. A failed, cancelled or revoked run cannot restart. Job erasure removes its packets, checkpoints, tickets and cached MCP payloads.

## Weekly review tickets

`POST /api/plinth/agent-runs/schedules` accepts one job's current identity and version, `starts_at` as an exact UTC timestamp, a `purpose` and explicit `confirm: true`. The weekly scheduler records one inert `review_required` ticket for a due week, with repeated delivery deduplicated. It reads no source contents, creates no executable run, starts no inference and dispatches no tools or notification. Inspect tickets through `GET /api/plinth/agent-runs/schedules`; pause a schedule with its `expected_version` at `POST /api/plinth/agent-runs/schedules/{id}/pause`. Recovered schedules remain inactive because their local consent is excluded.

An actual run still needs its own current source selection, preview and owner approval. Unattended AI, standing source grants, provider spending controls, complete forecast decisions and outcomes, notification delivery and installed owner-control screens remain unfinished. Existing provider grants, mail routing prerequisites and the ROLE-005 and ROLE-006 duties remain unchanged.
