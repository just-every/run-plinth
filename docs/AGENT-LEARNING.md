# Completed-job estimating drafts

The native owner can review selected completed jobs and give an agent access to that exact analysis packet. This does not grant access to other jobs, train an external service, certify warranty coverage or change an estimate.

1. Submit `POST /api/plinth/agent-learning/preview` with `catalog_id`, `catalog_version` and two to twenty `sources`, each containing its job `id` and current `version`. Choose jobs that used the assembly or template in their accepted estimates. Jobs must share a currency; assembly units must match. The preview includes the original quote and catalog references, retained dimensions, approved labor and production, recorded procurement variance and callback costs. Missing production and lifetime callback denominators remain unknown.
2. Inspect that preview. Submit the same selection to `POST /api/plinth/agent-learning/packets` with its `digest`, `confirm: true` and a review `reason`. Only a signed-in owner can create this consent. A changed source requires another preview.
3. The agent uses `plinth.learning.list`, `plinth.learning.read` and `plinth.learning.prepare` over MCP. Preparation takes a packet identity and an `input` containing a unique `request_id`, a reason and candidate changes. Assembly productivity and rate allowance changes are whole percentages between minus 25 and plus 25; the added risk allowance and resulting total waste allowance must be between zero and 25 percent. A rate allowance scales the assembly unit rates, rounded to cents, without revising the supplier rate record. Template drafts instead accept `dimension_percent` for the existing default dimensions, within the same change bounds.
4. Read the draft's observations, uncertainty and replay. Replay keeps each historical job's dimensions, dated rate revisions and signed revenue fixed. Candidate cost and margin are counterfactual values, never historical postings. A changed catalog or source, erasure, revoked consent or revoked agent authority refuses further agent access, including cached reads.
5. Reject a draft through `POST /api/plinth/agent-learning/packets/{packet_id}/drafts/{draft_id}/reject` with a reason. Rejected values remain in the owner's private history. To adopt a draft, a signed-in person reviews its `lesson_input` and uses the existing completed-job lesson proposal and approval doors under `POST /api/plinth/reports/performance/jobs/{job_id}/lessons`. The approval action remains separate. There is no agent approval tool. New estimates use an approved catalog version; signed estimates, original costs and previous catalog revisions stay fixed.

A packet's owner history is available from `GET /api/plinth/agent-learning/packets/{packet_id}`. Revoke its agent consent with `POST /api/plinth/agent-learning/packets/{packet_id}/revoke` and `confirm: true`. CLI archives preserve the packet and its draft and rejection history, but exclude consent. A restored installation must obtain a fresh owner review before any agent reads these sources. An existing hold on either source protects the shared analysis until the owner records its release. Erasing either selected source then removes the linked packets, drafts and cached agent payloads; later erasure journals fence older archives.

Procurement comparisons cover recorded native commitments, receipts and posted bill references. An unordered balance is not an actual saving. Callback records show recorded costs and repeat-case links; absence of a recorded case does not establish a defect-free lifetime. These facts support a human-reviewed proposal, not an automatic financial or professional decision.
