# Plinth target acceptance

Target edition: 17 October 2026. This matches every named clause in CONTRACT.md, including the retained published journeys. Retained status was judged at commit `58730bb834ea59a4ba62d0afcf1805c0dcf9a1d5`; later completed clauses cite their own named journeys below. A partial journey is not satisfied by its existing subset; the Gap in the contract states what remains. Missing journeys are build targets. The first buyer is a US residential builder/remodeler operating in USD; current AUD tests prove only the labelled published ledger.

Use ordinary signed-in pages, native HTTP/API, provider callbacks and the documented rer CLI. Use a real migrated database and real application behavior; fake only the paid/network provider edge. Named migration journeys require real owner-authorized exports; controlled provider transactions are required where stated. Use realistic data: a $480,000 fixed-price remodel, three trades, staged deliveries, a $7,500 allowance, a signed change, two draws and a warranty callback, plus a cost-plus job and a second job sharing a trade. Never contact real clients/subs or move real funds without specific authorization for that run.

For each build round run tests only for changed flows, stop development servers before verification and let CI run the full wall. Existing tests are `pnpm run test:plinth` (real Worker/D1 domain, CSV import and CLI portability), `pnpm run test:email-link` and `pnpm run test:site`; `rer check` validates the document/command contract. Use at most two test workers. For interface builds, complete every changed journey at 1440 and 390 pixels, including permission failures, long records and populated end states.
